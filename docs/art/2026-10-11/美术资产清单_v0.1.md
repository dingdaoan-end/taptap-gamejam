## 2. 统一美术方向

### 2.1 一句话风格

**像夜色里会唱歌的手绘庭院：奶油色小路穿过蓝绿草地，木质乐器守住中央的暖光，携带音符的墨团沿路涌来。**

- 2D 正交俯视、方格地面；物体可以略露正面以便辨识。地面格子保持水平／垂直，不使用菱形等距格。
- 手绘童话质感，边缘简洁，纹理柔和；缩小后先读轮廓，再读材质。
- 四区属于同一片场景，使用同一地表、道路和阻隔素材族。差异来自布局、稀疏装饰和轻微光色，不分别制作四套生物群落。
- 音乐来自“敌人带音高、塔提供音色”。怪物身体不画成钢琴、小提琴或其他乐器；塔也不因选择 Do／Mi／Sol 而永久变成不同属性塔。
- 三种怪的轮廓、三个音的徽记是两条独立信息通道；不能用同一套颜色同时表达怪物类型、音高和危险等级。

### 2.2 建议色板与层级

| 用途 | 建议色 | 使用规则 |
|---|---|---|
| 夜色底／深障碍 | `#18283D` / `#243746` | 大面积低饱和，避免与怪物轮廓连成一片 |
| 蓝绿草地 | `#416E68` / `#547F70` | 比路径低明度；不铺高频亮点 |
| 奶油石路 | `#D6C6A0` / `#B6AC91` | 形成连续、可追踪的路线；边缘不藏分叉 |
| 胡桃木／黄铜 | `#75503A` / `#BFA367` | 乐器与核心共享材料，黄铜只点缀 |
| 象牙琴键／文字 | `#F4E9CD` | 塔键与重点文字使用；非所有描边都发光 |
| Do | `#75D0C6` | 圆形徽记＋引擎文字“Do” |
| Mi | `#E8C774` | 菱形徽记＋引擎文字“Mi” |
| Sol | `#E78E7B` | 三角徽记＋引擎文字“Sol” |

数值用于统一起点，需在实际夜色与显示器上调整。灰度下仍须靠形状、唱名和怪物身体辨认。普通战斗不全屏闪白；共鸣也不覆盖敌人位置和琴键提示。

### 2.3 四区的视觉安排

| 区域 | 视觉建议 | 共用资产与制作约束 |
|---|---|---|
| 1 初见 | 草地开阔、清楚的转弯、少量树木；道路最易读 | 共用全部地表；不要用密集草丛盖住首次教学 |
| 2 应答 | 两支道路像交错的乐句，装饰在分叉外侧形成轻微对称 | 靠布局表达“应答”，不增加新地块机制 |
| 3 合奏 | 汇合口稍紧凑，明确出现矮墙或树丛的遮挡面 | 视觉上能识别哪块是真阻隔，不能只靠运行时红框解释 |
| 4 涌现 | 组合前三区素材，核心方向暖光略增强 | 不新增 Boss 场、商店、传送门或另一套地貌 |

按本次附件实测，每区横 25、纵 13 格，地块基准 64×64；单区原尺寸为 1600×832，四区为 3200×1664。这是资源规格，不要求地图在任何窗口中均以 1:1 像素显示。全览只展示总体关系，当前区镜头负责实际操作可读性。

## 3. 数量口径与 P0 总表

- **母版**：一项需要独立完成造型／绘制的基础图；同图旋转、镜像、缩放不增加母版。
- **变体**：在母版基础上额外导出的独立图。本表 P0 仅增加 2 张草地变体。材质调色、徽记组合、运行时状态不当作额外变体贴图。
- **帧**：在静态母版之外新增绘制的动画帧。P0 先用程序缩放、位移、透明度与粒子，**新增手绘帧为 0**；这不表示没有动画。
- 计数按独立 Sprite 条目统计，不按 PNG 文件数或图集张数统计。一张图集包含多个条目也仍按条目计数。

## 4. P0 逐项制作清单

尺寸写法为“建议原画画布 → 建议运行画布”。以 2 倍原画绘制供缩小检查，不追求大图细节。透明画布尺寸包含边缘留白；实际占地单独由关卡数据定义。

敌人底部地面接触点为移动锚点。静止视觉中心可以浮动，脚底标记与路径位置保持稳定。P0 身体使用朝向中性的正俯视造型，移动方向由位移和拖尾表达，不要求四向手绘帧。镜像不得镜像 UI 文字或音高徽记。

领奏塔仍然是 T01，使用选择角标和小键位提示区分状态，不增加“领奏塔”新类型或永久皮肤。T02 的三枚共振窗表达和弦角色，避免被理解为三座独立可拆塔。核心损伤先用暗化、短促震动和独立生命 UI 表达，不制作多档损坏母版。

03 概念板采用展示标签；导出时按本清单统一命名：板上 B01 CORE 对应 T03，P01 BUILD PAD 对应 G07，P02 PATH LANTERN 对应 D02，P03 BLOCKING WALL 对应 O03／O04。05 板的破柱、全景中的大拱门与水面只属环境氛围参考，P0 使用本表四类阻隔和四类装饰，不增加水域玩法或额外碰撞类型。

## 5. 动画与特效要求

P0 先做一致的时序和可读性。以下均可由静态 Sprite 与程序完成；“建议时长”不改变实际拍点，所有击杀、发声和谱点以同一音乐事件同步。

| 对象／事件 | P0 表现 | 程序替代方案 | 后续手绘帧建议 |
|---|---|---|---|
| 普通怪移动 | 每拍迈进时轻压扁，停稳恢复；徽记不跟随压扁 | 身体局部缩放与位移 | P1 可选 4 帧循环 |
| 快怪移动 | 短促向前挤压、尾部拖影，路径转角不瞬移出路 | 静态双尾＋少量残影 | P1 可选 4 帧循环 |
| 和弦怪移动 | 三核轻微异相起伏，整体保持一个落点 | 子节点偏移／缩放 | P1 可选 4 帧循环 |
| 怪物非致死受击 | 边缘瞬亮、短暂压缩，不喷彩色记谱音符 | 着色＋F01 | 不额外画帧 |
| 怪物死亡 | 墨团收缩散开，实际音高飞向谱线 | 缩放淡出、复用 F01／F02 与音高徽记 | P1 三类共用 4 帧消散遮罩即可 |
| 塔攻击 | 对应发声拍键位亮起、琴体轻回弹 | F04＋节点位移，约 0.1–0.2 秒回落 | P1 普通／和弦塔各 3 帧，可选 |
| 预约与锁定 | 空心音符进入槽；锁定后改边框状态；发声转实心 | UI 轮廓、填充与标签 | 不额外画帧 |
| 合奏休止 | 三个来源短线汇合，地面细环扩散，受影响怪物出现 M04 | 线段、F03、状态徽记；约 0.4 秒主要反馈 | 不画覆盖整屏的帧序列 |
| 漏怪／核心受损 | 核心局部抖动，生命图标减一；不全屏红闪 | 节点震动＋U05 | 不额外画帧 |
| 切区／最终回放 | 镜头平移／拉远，塔和核心按真实音符依次响应 | 镜头与既有发声反馈 | 不额外制作视频或假演奏动画 |

如果只追加一项帧动画，优先小怪移动。不能为动画增加“受击无敌”“死亡滞留挡路”等未设计的战斗规则。程序位移与身体变形分属父子节点，避免视觉动画改变逻辑位置。

## 6. 引擎交付与遮挡规范

### 6.1 文件与分层

- 命名采用上表 ID＋资源名，例如 `E01_enemy_single_body.png`。资源的可编辑原文件保留分层，导出图不带画板标题、说明、尺寸箭头或装饰边框。
- 输出标准 RGBA PNG、透明背景、sRGB 色彩。PNG 外观需检查黑底与白底，不能有灰白毛边。概念板背景不能被误当作透明像素。
- 地表与道路满格输出；物体允许留白，但同一类的画布和落点统一。图集打包时留出扩边，避免缩放出现接缝；是否压缩与过滤由实际构建检查决定。
- 建议全项目以 64 PPU 起步，让一个 64×64 地块对应 1 个世界单位；若现有工程采用其他尺度，先统一换算，不只改单个资产。手绘路线优先双线性过滤，并在目标分辨率检查；无需强行按像素画的 Point 模式显示。
- 音高徽记、UI 文字、影子与对象主体分离摆放。P0 影子可使用 F04 暗色拉伸，避免为每个对象额外导出一张阴影。

### 6.2 Pivot 与 Sorting

| 对象 | Pivot／排序依据 | 必须遵守的边界 |
|---|---|---|
| Tile 与地面标记 | 画布中心，地面固定层 | 路边纹理不能改变可走格，建造位图不能自行赋予建造资格 |
| 塔、怪、阻隔 | 统一地面接触点；按脚底位置排序 | 视觉高度不等于碰撞体积；同类切换状态不改变落点 |
| 核心 | 底部接地中心，独立核心层或明确的脚底排序 | 四向接路的位置在场景里设置，不写进装饰图形 |
| 徽记、血量、休止 | 跟随对象的稳定屏幕上方锚点 | 不被树冠或塔身盖住；近邻重叠需错位／收紧，而非放大整张怪图 |
| 射程／遮挡预览 | 在地面上、对象下；独立有效／无效样式 | 与战斗共用判定；颜色以外还要有实线／斜纹区别 |

蓝图中的阻隔格同时不可走、不可建、阻断视线；O01–O04 必须绑定明确格子占用。树冠在画面上伸到邻格时，不能让玩家误以为邻格也阻挡；选塔预览时应淡化遮住目标的上半部，地面根部仍可识别。D01–D04 均为无阻隔装饰，不能复用成强阻隔但仍保持同一外观。

### 6.3 UI 与可读性

游戏规则文字全部用引擎字体显示，选用已核对授权且覆盖简体中文的字体；提交包附字体许可。对外可见界面不要出现图生图提示词、资产编号、版本号或工程调试字段。

以 1280×720 和 1920×1080 两档检查当前区镜头：路线连续、单怪占地清楚，音高文字和按键不靠放大截图才可读。单区若横向展示 25 格，不要默认 32 px 原始徽记缩小后仍可用；徽记应通过 UI 保持合理屏幕尺寸，并在拥挤情境实测。全图缩略镜头不要求每个音高可读，此时不进行领奏操作。

## 8. 逐项验收

1. **关卡语义**：按附件逐格拼出每区 25×13 网格；道路格、障碍格和基地格均与 v0.2 数据一致。路径、基地、预设建造位与阻隔由实际对象／数据决定，不能用一张完整贴图替代。美术必须能在 Scene 里逐个移动和替换。
2. **连续拼接**：直路、连续转弯、内凹、T 口、十字口与地图边缘，在缩放后的实机视图没有露底缝、错向阴影或误导性的断路。
3. **身体识别**：去掉音高徽记和颜色后，普通／快速／和弦怪仍能凭轮廓分清；和弦怪始终被理解为一个三核目标。
4. **音高识别**：Do 圆、Mi 菱、Sol 三角在灰度和常见色觉模拟下仍可辨；唱名清楚，徽记不随身体挤压或镜像。快怪也能携带三种音高，不把“快”固定成某音。
5. **大小与占地**：在实际游戏镜头、最拥挤波次下检查；塔不压住相邻路格目标，树冠淡化后仍能看清敌人位置和提示。建造、遮挡与贴图外轮廓的差异有明确预览。
6. **行为真实**：无目标按键只出现预约／休止反馈；非致死不出实际音符；击杀、发声、谱点同步。和弦怪的三音不能表现成三次金币击杀。
7. **共鸣因果**：看得到哪些塔贡献音，哪些存活敌人获得休止；新生敌人不被误画成已受影响。特效结束后路线与选择状态仍清楚。
8. **文件可用**：PNG 真透明、Pivot 记录齐全、ID 唯一、母版和变体可追溯；字符未烘焙进美术；依赖的字体／外部素材有许可与来源记录。
9. **数量可核对**：P0 清单共 37 母版、2 衍生变体、0 新增手绘帧。未制作、已出原画、已导出、已进引擎、已验收这五种状态分别记录，不能把概念图完成当成运行资产完成。

## 9. Jam 制作顺序与减法

### 9.1 M1：只证明 16 拍演奏

先制作或整理 G01 草地、G02 路面、G07 建造位、G08 入口、T01 钢琴、T03 核心、E01 普通怪、M01–M03 三音徽记、F02 音粒、F03 共鸣环：**12 个母版**。用程序矩形先补路线边界、按钮、血量和节拍提示；无需先完成五张图中所有细节，也无需先制作快速怪、和弦怪或四区装饰。

小样用一座领奏琴塔＋两座自动琴塔；显示真正的击杀、三音共鸣与休止。先在真实画面证明手奏归因，再扩展全清单。

### 9.2 P0 制作顺序

1. 确认塔、普通怪、音高徽记同屏缩小后的比例与对比。
2. 补齐道路拼接与阻隔；先搭一条能运行的正式路径，检查预览和实际遮挡。
3. 补快速／和弦身体与和弦琴塔；验证不同类型不会靠颜色误判。
4. 补必要 UI 与共鸣反馈，接入真实音乐事件。
5. 复用素材完成四区；最后添加装饰、镜头与环境光。

### 9.3 时间不足时怎么删

- 第一刀：删除 4 个 D 类装饰母版，以及 2 个草地变体。保留道路、轮廓与节拍提示。
- 第二刀：阻隔先只做 O02 密实树丛和 O03 直墙，以布局而非新造型区分区域；其余两个障碍母版延后。
- 第三刀：所有移动、攻击和死亡继续采用程序动画；不进入 P1 手绘帧生产。
- 第四刀：减少每区波次数与演出长度，继续共用同一套地表。不要删掉音高唱名、手奏提示、真实射程预览或独立对象编辑能力。

删减后仍须让玩家一眼看出路、怪、可建造位置和自己的领奏塔，并能看懂“我的选择让哪一个音响起”。美术首先服务这个因果链。
