# 节拍攻击

## 当前玩法

- 进入 `MusicTest` 场景并 Play，通过原来的建造菜单放置 Bell、Chord 或 Duduk 塔。
- 敌人进入实际 AttackRange 后，塔等待背景音乐的下一个攻击拍点再攻击。不会在进射程的瞬间扣血。
- 默认每拍命中一名敌人，伤害 1；敌人默认生命 3。攻击显示短促连线，受伤闪红，生命归零立即退场。
- 发出攻击前重新检查范围。敌人已经走出射程、被其他塔击杀、塔被拆除或范围被禁用时，不会继续命中旧目标。
- 音乐暂停时停止攻击；恢复沿用同一音乐相位；重启重新开始。掉帧不会补发一串历史攻击。
- 建造条件和红绿预览保持现有设置，不能建造时不显示文字提示。

`Map` 和 `MusicTest` 的建造菜单均引用继承了攻击组件的塔。`MusicTest` 已有敌人生成器和路线，适合直接测试战斗；`Map` 仍保持原有场景布局。

## 在 Unity 中修改

在 Project 里选择 `Assets/Prefabs/Tower.prefab`，修改 `Tower Beat Attack`。Bell、Chord、Duduk 都继承此设置，也可在各自 Prefab 中覆盖。

| 字段 | 用途 |
| --- | --- |
| Pattern Beats | 重复模式的拍数，默认 4 |
| Attack Beats | 模式内从 0 开始的拍点；默认 0、1、2、3，每拍一次 |
| Damage | 单次命中伤害 |
| Detector | 当前塔的实际索敌范围组件 |
| Firepoint / Attack Color | 连线起点与颜色 |
| Max Late Seconds | 游戏卡顿时允许命中的迟到窗口，默认 0.12 秒 |

例：`0、2` 在每小节第 1、3 拍攻击；`1、3` 在第 2、4 拍攻击；`0.5、1.5、2.5、3.5` 使用半拍；清空列表表示休止。建议退出 Play 后修改 Prefab，重新运行验证节奏。

选择 `Assets/Prefabs/Enemy.prefab` 的 `Enemy Health / Max Health` 修改敌人生命。

所有攻击使用 Castle 上的同一个 `MusicClock` 和 DSP 时间。BPM 在该组件修改后 Restart 生效。当前两张场景的鼓声使用现有 `Lv.1 Drums.wav`：100 BPM、32 拍、19.2 秒。Map 原来失效的鼓声引用已修复。

现有 Bell 和 Chord 控制器继续播放其音乐声部；攻击没有额外叠加枪声。攻击拍点是可编辑的节奏表，本版不自动分析 WAV 中每个音符的起音。要让攻击严格对应某段旋律的所有音符，需要按该段谱子填写拍点。

## 验证入口

- `dotnet run --project Tests/BeatAttack.CoreTests`：纯拍点与统一时钟边界测试。
- Unity `BeatAttackChecks.RunBatch`：真实 Prefab、范围、伤害、死亡、换目标、休止、暂停、恢复、重启和卡顿测试。
- Unity `BeatAttackPlayChecks.RunBatch`：在 MusicTest 中进入真正 Play 模式，验证实际生成、三次按拍伤害和死亡流程；临时测试对象与速度不保存到场景。
- `Tools → Combat → Configure Beat Attack Prefabs` 可为基础塔和敌人补装组件，已有参数会保留。
