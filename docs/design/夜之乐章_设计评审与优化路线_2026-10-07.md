# 《夜之乐章》设计评审与优化路线（2026-10-07）

> 评审身份：资深游戏策划（外部视角）
> 评审对象：灰盒 v0.2 = 单夜钢琴塔防（含装饰音怪、分档乐句祝福、索定滤镜、终止式、击杀回放）
> 依据数据：示例布局机器基线——44/44 击杀、据点 10/10、4/7 乐句完整、41 音符、1599 分、单夜 112 拍 ≈ 61 秒；经济全程无压力
> 阶段背景：TapTap GameJam 21 天赛程，当前处于 W1（验证周），设计文档 v1.1 为基准

---

## 0. 评审前提：先补齐这些关键信息（按重要性排序）

本次评审基于灰盒实机数据与设计文档，以下信息缺失会直接影响结论的置信度，建议在 playtest 前补齐：

| # | 缺失信息 | 为什么关键 | 建议获取方式 |
| --- | --- | --- | --- |
| 1 | **可听性盲测结果**（3–5 个不玩游戏的路人听回放，能否哼出旋律轮廓） | 设计支柱"旋律从战斗中涌现"成立与否的唯一证据；当前 41 音符的记谱序列是否"好听"完全未验证 | D1–D2 内做完，风险①的门禁标准 |
| 2 | **交付平台形态**：TapTap 评审要求 PC 包还是移动端可玩包？ | 当前构建仅 Windows + 键鼠操作；若要求触屏，全部交互需重新设计——这是交付日硬风险 | 立即查 Jam 规则页 |
| 3 | **Playtest 行为数据**：真实玩家的通过率、完整乐句率、漏怪归因、平均局时长、"看不懂什么" | 目前所有难度结论来自机器基线（示例布局完美通关），人对拍的概念理解速度未知 | W1 周末找 3–5 人，录屏 + 事后三问 |
| 4 | TapTap GameJam 评分维度权重（玩法/创新/完成度/表现力） | 决定 W3 打磨资源投向（演出 vs 内容量） | 查规则页或往届复盘 |
| 5 | 赛后是否商业化、目标用户画像 | 决定留存/社交/付费三个维度按"Jam 版"还是"长线版"投入 | 团队决策，建议 Jam 后再定 |

以下分析对维度四、五采取**双时间层**处理：Jam 期（21 天内）重新定义为传播与重复可玩性；赛后（长线）再谈完整留存/付费。

## 1. 总体判断

**核心循环已闭环且钩子独特**："布塔 → 按拍防守 → 击杀成曲 → 聆听回放"在 1 分钟内可完整体验；"结算时回放你的战斗变成的曲子"是同类竞品（节奏地牢、Patapon、Loop Hero）中没有直接对标的记忆点，具备评委 30 秒讲清楚的表达力。

**当前三个最大设计风险**（按危害排序）：

1. **涌现的可听性未验证**——一切玩法深度的前提，若记谱序列听起来是噪音，全部数值设计失去意义；
2. **挑战性不足且难度不可归因**——示例布局 44/44 完胜说明"最优解免费"，玩家感知不到"我在做取舍"；装饰音怪机制进场但对示例布局零压力；
3. **平台适配悬空**——若 TapTap 要求移动端，当前纯键鼠 IMGUI 原型在触屏上不可用。

## 2. 分维度诊断与优化建议

### 2.1 核心玩法与数值设计

**现状问题**

| 问题 | 证据 | 危害 |
| --- | --- | --- |
| 1HP 世界导致祝福系统退化 | 敌人全部 1 血即杀，强奏（+伤害）/柔板（减速）无载体，祝福只剩延音（回血）一族 | 设计文档 §6.1 三选一装配无法实现，策略层薄 |
| 判定过宽，乐句近乎自动完成 | do–mi–sol–do′ 仅 4 音、16 拍窗口、子序列 + 间隔 ≤4 拍；机器基线 4/7 完整 | "作曲感"是白送的，玩家没有为目标做过取舍 |
| 经济无张力 | 开局 24 币 + 全程击杀 44 + 祝福约 +8，支出上限 8 塔 ×8=64，终局币过剩且无处可花 | 建造决策空洞化，中后期"躺赢" |
| 滤镜收益不可见 | 玩家设"跳过 la"后无法预知换来什么（谱面推进？漏怪风险？） | 方案 B 的核心交互缺乏反馈闭环 |
| 旋律固定 | 全程只盯 do–mi–sol–do′ | 重玩同质化，多局后无新目标 |

**优化建议**

- **A1｜可听性盲测与量化方案选型**（P0·短期）：3–5 人盲听三种量化（严格拍点/半拍容差/音阶吸附），选轮廓辨识率最高者；不过则回退"击杀触发预排旋律"。理由：风险①门禁，先于一切内容投入。预期效果：把"好不好听"从主观争论变成可决策数据。
- **A2｜调参面板化**（P0·短期）：装饰音数量、敌人 HP（1/2/3）、波密度、旋律长度做成配置表 + Editor 菜单一键切换。理由：W1 周末 playtest 后必须快速改数值，硬编码会拖死迭代速度。预期效果：数值调一轮 ≤30 分钟。
- **A3｜引入 2–3 HP 敌人（和弦怪前置）**（P1·短期）：让强奏/柔板有语义载体，塔的输出差异显性化。理由：解锁祝福三选一与塔定位分化，是数值系统的地基。预期效果：策略空间从"放哪"扩展到"放什么+祝福装什么"。
- **A4｜金谱线与曲调选择**（P1→P2·短期）：锁音色判定 ×1.5 奖励；曲库 6–8 条按夜解锁。理由：同关卡多解法是重复可玩性的最低成本来源。预期效果：二周目动机。
- **A5｜自由编谱 + 可行性校验**（P3·长期）：玩家自设旋律时系统校验"本夜音高供给能否达成"，标红不可行音。理由：涌现玩法的终极形态，但需要防挫败设计，Jam 期不做。

### 2.2 关卡与难度曲线

**现状问题**

| 问题 | 证据 | 危害 |
| --- | --- | --- |
| 难度=数量堆叠，非机制组合 | 三波仅密度递增，新机制只有装饰音一种 | 二三波体验趋同 |
| 隐藏知识 | 装饰音只走偶数列、间隔 ≤4 拍规则，仅 README 有写 | 不读文档的玩家把机制当 bug |
| 间奏太短 | 8 拍 ≈ 4.4 秒，不够重新布阵 | "间奏重整"设计名存实亡 |
| 失败无归因 | 漏怪只报数量，不提示原因（快怪突进/覆盖空洞/金币不足） | 挫败感指向系统而非自己的决策 |
| 单夜结构 | 61 秒一局，无难度分层 | 演示容量不足以支撑 5–7 分钟目标体验 |

**优化建议**

- **B1｜每波考题显性化 + 失败归因**（P0·短期）：波次开场一行文案（"本波：装饰音抢拍，试试跳过筛选"）；漏怪时红字归因（"2 个装饰音漏网"）。理由：机制透明是"玩家觉得自己聪明"的前提。预期效果：教学成本从 README 移进游戏内，挫败转化为策略线索。
- **B2｜地面节拍点与装饰音轨迹预览**（P0·短期）：通道格画拍点、装饰音行进列高亮偶数列。理由：把偶数列特性从隐藏知识变成可读信息。预期效果：布塔决策有据可依。
- **B3｜间奏延长至 16 拍或允许暂停建造**（P1·短期）：理由：重整需要 10–20 秒思考；预期效果：间奏成为真实的战术节点。
- **B4｜三夜结构 + 考题矩阵**（P1–P2·系统）：夜 1 教学序、夜 2 机制组合（和弦怪/音痴怪）、夜 3 Boss 终止式；每夜一道主考题 + 两道副考题（设计文档 §4.4 已有框架，需落成波次表）。预期效果：61 秒 → 5–7 分钟完整体验，难度曲线有台阶。
- **B5｜动态难度**（P3·长期）：连续两乐句 0 层则下调填充音比例，两漏怪以上给塔位建议。理由：赛后扩大受众面。

### 2.3 操作体验与 UI 交互

**现状问题**

| 问题 | 危害 |
| --- | --- |
| 音画反馈只有线段与飘字，"音符诞生"无仪式感 | 涌现主题的表达力折损，演示冲击力不足 |
| 无引导流程（仅左下三行文案） | 首次进入的 30 秒流失风险 |
| 建造/选择双模式 + B 键切换，误操作面大 | 110 BPM 下操作压力大 |
| 触屏零适配（若移动端交付） | 交付日硬风险：hover 预览、Delete 回收、B 键均无触屏等价物 |
| IMGUI 全程序化 UI | Jam 期是优点（改版快），赛后是天花板（无动画/粒子/布局系统） |

**优化建议**

- **C1｜击杀粒子=可视化音符 + 祝福逐格点亮演出**（P0–P1·短期）：击杀处爆出对应音高色的音符符号并飞向底部琴键；乐句结算时 4 格 pips 逐格点亮 + 终止式全屏波纹。理由："看见旋律从战斗中长出来"是评委与玩家理解涌现的最短路径。预期效果：演示视频质感跃迁，回放段落的情绪峰值。
- **C2｜首夜前 16 拍分步引导**（P1·短期）：放塔→开战→第一次记谱各一步高亮指引，可跳过。预期效果：30 秒上手。
- **C3｜触屏交互方案验证**（P0 决策 + P1 实施）：若移动端交付——点击=建造/选择（已有）、长按=回收、双击塔=循环切换滤镜模式、波间整备期放大操作热区。理由：平台错配是评审一票否决项。预期效果：移动端可玩性兜底。
- **C4｜渲染层迁移（Sprite + 粒子系统）**（P2→赛后·长期）：W3 只做最小集（击杀粒子、敌人态），完整迁移赛后。理由：IMGUI 到顶了。

### 2.4 玩家留存与社交机制（Jam 语境：传播力与重复可玩性）

**现状问题**

- 单局 61 秒 + 旋律固定 → 第二局动机弱；
- 无 meta 目标（收集/图鉴/挑战）；
- 最强的传播资产（击杀回放）目前只在结算页内部播放，无法带出游戏。

**优化建议（双时间层）**

- **D1｜结算分享卡**（P1·短期·传播核心）：结算页一键截图/导出：本局得分、星级、乐句完成度 + "聆听乐章"回放按钮（录屏友好）。理由：Jam 的"留存"就是自来水传播，回放是天然 UGC 素材；TapTap 论坛晒图是最低成本获评路径。预期效果：玩家帮你在评审期做宣传。
- **D2｜曲库收集（局内 meta 最小版）**（P2·短期）：三夜分别解锁新曲调，结算页展示"已谱写 3/8 段旋律"。预期效果：多局目标感，成本极低（复用曲调库）。
- **D3｜每日一谱**（P3·长期）：固定 seed 波次 + 指定旋律的全服挑战，附带本地最佳纪录（TapTap 云排行榜需平台能力确认，列入信息缺口）。预期效果：赛后 DAU 支柱。
- **D4｜异步好友对决**（P3·长期）：同一谱面比分数/比"还原度"（完成度×音色匹配），无需实时联网。理由：音乐题材的社交天然适合"晒作品"而非对抗。

### 2.5 付费与经济系统

**Jam 期结论（P0 决策）**：不做任何付费。TapTap GameJam 评审维度是创意与完成度，付费设计零收益且挤占 21 天工期。

**局内经济修正（进 Jam 版）**

- **E1｜终段回收阀**（P1·短期）：波间整备开放"乐章商店"——用过剩金币购买即时祝福（+1 层）、临时扩射程、下一波减速。理由：终局 50+ 币无处可花=决策空洞；商店把过剩资源转成战术选择。预期效果：经济闭环 + 间奏变成有内容的阶段。
- **E2｜难度与奖励挂钩**（P1·短期）：高填充音比例的波次击杀币 +50%。理由：让"难"有对价，玩家才愿主动挑战乱序。

**赛后商业化框架（P3·长期，供决策参考）**

| 方向 | 建议 | 理由 |
| --- | --- | --- |
| 定价模型 | 买断制 ¥6–12（移动/PC 同价）或免费 + 曲包 DLC | 单机音游调性匹配；音乐内容天然适合 DLC（新乐器=新玩法+新曲库） |
| 内购红线 | 只卖内容（曲包/乐器/皮肤），不卖数值 | 数值付费会摧毁"防御即作曲"的公平体验 |
| 广告 | 不建议激励视频复活/双倍；若做仅限"解锁回放导出"类非核心位 | 广告打断心流与音乐题材强冲突 |
| 数据前提 | 需补充：目标用户付费意愿、同类（节奏地牢手游版）定价带 | —— |

## 4. 本周速赢清单（按性价比排序）

1. **可听性盲测**（半天）——决定后面 20 天的一切；
2. **失败归因 + 波次考题文案**（半天）——把挫败变线索；
3. **击杀音符粒子 + 祝福点亮**（1 天）——演示质感最大杠杆；
4. **调参配置表**（半天）——解锁快速迭代；
5. **平台形态确认**（10 分钟查规则）——避免交付日翻车。

## 5. 一句话收束

这款游戏的胜负手不在系统数量，而在**"玩家能否在 30 秒内看见并听懂：我的防守变成了一首曲子"**——所有 P0 项都应服务于这句话，所有 P1+ 项都不应损害这句话。
