# 铃铛塔与和弦塔循环

关卡一、二使用同一个 Castle `MusicClock`（100 BPM）。每个切片 4 拍、2.4 秒。

## 铃铛塔

`Tower_Bell.prefab` 的 `BellTowerMusicController.Loops` 按以下顺序引用资源：

| Loop | 文件夹 | 组内切片编号 |
|---|---|---|
| 01 | LV1_Bell_Loop_01 | 01、02、03、04 |
| 02 | LV1_Bell_Loop_02 | 05、06、07、08 |
| 03 | LV1_Bell_Loop_03 | 13、14、15、16 |
| 04 | LV1_Bell_Loop_04 | 21、22、23、24 |
| 05 | LV1_Bell_Loop_05 | 29、30、31、32 |

成功创建的铃铛塔依次分配 Loop 01、02、03、04、05、01……，同时独立轮流分配第 1、2、3、4、1、2……拍。分配记录由当前场景的 MusicClock 保存，塔的 Inspector 在运行时显示 Assigned Loop 和 Assigned Beat。

| 建造顺序 | Loop | 拍位（每四拍中的位置） |
|---|---|---|
| 1 | 01 | 第 1 拍 |
| 2 | 02 | 第 2 拍 |
| 3 | 03 | 第 3 拍 |
| 4 | 04 | 第 4 拍 |
| 5 | 05 | 第 1 拍 |
| 6 | 01 | 第 2 拍 |

一座塔始终播放分配到的组，组内四段依次循环，总长 16 拍。取得目标后，在下一个留有音频调度提前量的所属拍位加入；例如第 3 拍的塔在全局拍数 2、6、10、14……开始完整播放切片（全局拍数从 0 计）。没有目标不安排下一段，已经开始的段落自然播完。重新取得目标时继续组内顺序与原拍位。

铃铛塔的 `TowerBeatAttack` 直接读取 `BellTowerMusicController` 已排定的切片起始拍，每段开始时攻击一次，每四拍一次；不另算加入时间，也不再使用 Prefab 中的通用 attackBeats 数组。未排定音频、暂停或控制器停用时，不产生新的铃铛攻击。目标与伤害仍在攻击时校验，卡顿过久的攻击会跳过，不补发。

拆塔不回退分配顺序；停用／启用、暂停／继续、音乐停止／启动都不重新分配 Loop 或拍位。暂停会取消已排定的声音和攻击，恢复后在原拍位重新播放被中断的完整切片，不会立即插入一次攻击。关卡重新开始并清除玩家建造内容后，`MapUIFlow.RestartCurrentLevel` 重置两项分配，下一座塔从 Loop 01／第 1 拍开始。未来关卡切换的清图流程可调用 `MusicClock.ResetBellLoopAssignments()`，必须在清除旧塔后调用；该方法同时重置 Loop 与拍位计数。

## 和弦塔

`Tower_Chord.prefab` 按文件编号引用 Chords_4BeatSegments 下的全部 8 段，按 01 → 02 → … → 08 → 01 循环，总长 32 拍。

全局段编号由 `floor(全局拍数 / 4) % 8` 决定，段内位置为 `全局拍数 % 4`。新塔取得目标后在下一个可调度的整拍加入，读取该拍对应的音频及采样位置，与已播放的和弦塔保持同段、同位置。例如第 10 拍加入时，播放第 03 段，并从该段第 2 拍偏移开始（拍数和偏移从 0 计）。

失去目标不会停止全局段落推进。重新取得目标、暂停恢复或重新启用后，仍从当时的全局段落与位置加入。

## 验证

- `Tests/ChordPhraseTimingTests.cs` 检查四拍边界、32 拍回绕、延迟加入和暂停恢复的节拍位置。
- `Tools > Audio Loops > Run Bell and Chord Play Checks` 在保存好的 Map 场景中运行实际 Prefab 与 AudioSource 检查，完成后退出运行模式，不保存测试对象。报告：`Artifacts/TowerMusicLoops/play-check.txt`。
- 验证期间使用有生命值的静止敌人，并将测试音源静音；检查四个拍位的实际音源采样偏移、伤害触发拍数、四拍攻击间隔，以及暂停、目标重入和重开后的行为，同时回归和弦塔全局同步。不将其视为主观听音验收。
